# Final Project — Agile/Scrum Process Demonstration

## Overview
This project was created to demonstrate my understanding and practical application of the **Scrum framework**.T he goal here was to simulate a real-world Agile workflow by building out a product backlog, organizing work into sprints, and managing issues through a full development lifecycle.

## What I Did
Using GitHub Projects, I structured a Scrum board that mirrors how a real development team would operate. I wrote user stories from scratch, organized them across the backlog, and tracked their progression through each stage of the workflow.

## Scrum Board Columns
The board follows a standard Scrum workflow:

| Column | Description |
|---|---|
| New Issues | Freshly created items, not yet triaged |
| Icebox | Pending stories not ready for active planning |
| Product Backlog | Refined stories ready to be picked up |
| Sprint Backlog | Stories committed to the current sprint |
| In Progress | Actively being worked on (WIP limited) |
| Review/QA | Completed work awaiting review |
| Done | Fully completed and accepted stories |

## User Stories Written
I authored 10 user stories covering a product catalog domain, including:

- Creating, retrieving, updating, and deleting products (core CRUD operations)
- Liking and disliking products
- Listing and querying products
- Cloud hosting requirements
- Automated cloud deployment (CI/CD)

Stories were labeled as either `enhancement` or `technical debt` to reflect real-world backlog categorization.

## Key Scrum Concepts Demonstrated
- **Backlog grooming** — stories were refined and prioritized before sprint planning
- **Sprint planning** — a subset of backlog items were selected and assigned to Sprint 1
- **WIP limits** — the In Progress column tracks active vs. capacity (e.g., 1/3)
- **Story estimation** — estimates were applied at the column level to track team capacity
- **Technical debt tracking** — non-feature work was explicitly labeled and managed
- **Definition of Done** — completed stories were moved to Done only when fully accepted

## Purpose
This board serves as a portfolio artifact to showcase my ability to think and operate within an Agile environment — including writing clear user stories, managing a sprint, and understanding the full lifecycle of work from ideation to completion.
